# 可审阅的项目记忆（M4 开发切片）

本能力尚未发布到 npm；需要使用当前开发工作区构建的 CLI。它保存你显式确认的稳定项目约定，不自动记录聊天，也不改变权限。

## 适用范围

- 构建/检查命令：例如修改源码后运行 `npm run check`。
- 编码约定：例如内部模块采用现有的结构化错误类型。
- 架构决策：例如 Provider adapter 不负责权限决策。

记忆、RAG 和会话分别负责稳定约定、可溯源资料和当前任务连续性。不要将长文档、秘密、审批授权或“所有检查已经通过”这类临时执行结论存为记忆。保存命令不是执行命令或预先批准执行。

## 使用

在同一工作区启动交互式 CLI，输入：

```text
/memory add build-check
```

依次选择类型、输入内容、可选来源文件，再审阅完整预览，输入 `y` 并提交才保存。来源必须是工作区内相对路径，例如 `package.json` 或 `docs/architecture.md`；不能访问外部路径或敏感文件。留空表示用户确认的约定，而不是独立核验过的事实。

```text
/memory status
/memory list
/memory inspect build-check
/memory edit build-check
/memory refresh build-check
/memory remove build-check
/memory off
/memory on
/memory clear
```

`edit` 重新输入完整正文及来源；来源留空会移除原文件关联。`refresh` 保留正文、重新读取来源指纹，仍需预览确认，不能自动把旧结论变成新事实。删除与清空也需确认；清空只影响当前工作区。关闭注入不会删除本地条目。

关闭、删除或失效只阻止后续记忆注入，不会抹除旧对话中模型已经复述的内容。要检验关闭后的隔离效果，请新建会话，不要把旧聊天上下文中仍存在的文字当成记忆继续注入。

## 失效与预算

保存文件来源时记录 SHA-256。每次装配请求前重新核对，文件变化记为 `stale`，丢失、不安全或不能读取记为 `unavailable`；两类均不注入。先重新核对内容，再 `edit` 或 `refresh`，不要盲目重新确认。

没有文件来源的约定显示“用户确认（无文件来源）”，系统不能自动判断它是否已过时，应主动修订或删除。记忆只指纹核对来源文件，不把整份文件正文注入请求，也不证明正文中的结论正确。

- 每工作区最多 32 条；单条正文最多 1 KiB UTF-8。
- 可选来源文件最多 256 KiB，必须是有效 UTF-8 文本。
- 存储文件最多 128 KiB；上下文注入总计最多 8 KiB。已知模型窗口时还取 `窗口 tokens × 2% × 3 bytes` 的更小预算；这是保守字节额度，最终请求仍由 ContextManager 核对，不是精确 token 估算。
- 按稳定键顺序装配，超预算只省略完整条目并标明数量，不截断半条事实；当前没有相关性排序。
- 空记忆或关闭时没有记忆提示，不增加 Provider 调用。开启后会增加有界输入文本和本地文件核对成本，不宣称节省 tokens 或已证明改善模型表现。

## 存储与安全

```text
~/.syzzz-code/memory/<canonicalWorkspaceSha256>.json
```

按实际工作区路径隔离，同一目录的不同会话共享；目录链接别名解析到同一 canonical root。搬迁目录后不会自动继承旧记忆，第一版不提供迁移或同步。

存储为本地明文，文件采用原子替换、排他写锁和确认前后的 revision/source 复核，尽力使用 `0600`。Windows 的 chmod 不等于已经验证私有 ACL；同一用户权限下的其他进程仍可能改文件。这不是 OS sandbox 或防篡改签名系统。

目录重定向、文件链接、超限或损坏数据会阻止加载和覆盖，并显示不健康状态。异常遗留的 `.lock` 不自动抢占：先确认没有正在保存的 Syzzz 进程，再保留并检查该锁。损坏 JSON 也不会被清空命令静默覆盖，应先备份检查。

记忆以临时、用户级上下文装配，不能覆盖当前明确要求、系统、模式、审批、Hook、MCP 或路径规则。模型没有保存记忆工具，普通工作区文件工具也拒绝直接访问 `.syzzz-code/memory`，包括从主目录或目录别名启动。提供的保存入口是本地命令与确认；经另行批准的 Shell/扩展以及同用户外部进程仍有 OS 文件权限，不构成绝对防写承诺。

输入内容与确认答案不进入 Composer 历史、审计正文或会话显示历史；Slash 命令本身仍可进入用户输入历史。模型正常回答中主动复述的内容仍遵循原会话保存规则。

**开启后的有效记忆会随请求发送给当前 Provider，包括远程模型。** 预览已明确提示这一点；不要保存密钥、公司机密或其他不应发给该 Provider 的内容。没有自动 DLP，也没有因“用户确认”就保证模型不会误用文字。

## 验证与后续

运行 `npm run test:memory`；完整 `npm run check` 也包含该测试。专项使用隔离临时目录与固定 Provider，验证确认、取消、来源失效、并发、损坏/链接边界、真实交互输入历史隔离、模式拒绝和无额外模型调用。

专项证明工程与安全契约。开发阶段还使用真实模型验证了开启、关闭、来源失效和工作区隔离，共 8 条短任务轨迹通过；不等于复杂交付成功率提高或真实模型已稳定遵循全部记忆。自动提炼、跨项目搜索、语义排序、可写 Subagent 记忆、云同步和 Jev 记忆裁判均未实现；应在有独立需求和对照后再决定。
