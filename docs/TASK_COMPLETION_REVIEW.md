# 组合任务执行自查：实现与验收

## 范围与目的

本阶段承接 Prompt 整理和空检索恢复，处理单回合“查知识库，再检查本地文件”的漏步问题。
不训练模型，不增加前置意图分类器，不修改权限、检索排序、知识库或跨轮追问策略。
这是一项开发实验，不是模型理解能力或企业生产质量的认证。

基线为 `cee3525`，首轮实现为 `eb872c3`，冻结评测工具与题集为 `d486e7c`。
默认关闭的收口提交为 `1a8c1ef`。

**最终决定：保留实现和测试，但实验默认关闭。此次未通过组合任务质量验收，不标记 Validated 或 Frozen。**
普通 CLI 不启用它；开发评测通过 `QueryEngineOptions.experimentalTaskCompletionReview: true` 显式启用，未新增用户配置或环境变量。
以下实现说明均指实验开启时的行为。关闭时保持原有提示、RAG 输出预算与收尾方式。

## 原因与改动

原 Runtime 在读到 RAG 正文后，统一要求最多两句回答并停止，同时限制 128 个输出 tokens、在空行处停止。
这适合简短证据问答，却与“读完资料还要检查本地文件”的要求冲突。

新增 `src/task-execution.ts`，把三个概念分开：

1. 用户原始请求：是否真正要求读文件，仍以它为准。
2. 文件提及：只通过语法识别最多四个常见扩展名路径，不等同于任务、授权或意图识别。
3. 执行事实：记录至多十六条工具名、结果状态和有界 Read 路径。不把模型自述当作执行事实。

只有实际发生 RAG 操作且当前请求提及文件时，才注入这份回合内状态。
对于这样的组合场景，取消“读到 RAG 就结束”的指令，正常工具阶段输出预算改为 512 tokens；单独 RAG 问答和强制收尾保留原预算。

如果模型准备无工具结束，但提到的文件还有未尝试读取的，则最多增加一次自查机会。
未完成草稿先缓冲，不将其作为额外用户消息写入历史；下一次请求只增加真实执行状态和条件式提醒。
模型仍必须依据原始请求决定是否继续，不允许因为提及文件就自动读取。

## 具体边界

- 成功 Read 仅证明返回范围被读取，不证明分析正确、测试运行或整个文件已审查。
- 文件不存在时记录实际失败，不伪装完成，不重复提醒读同一文件。
- 遇到拒绝或取消，不触发额外自查。自查仍受原有调用数、工具轮数、token 和取消预算约束。
- 普通对话不增加模型调用。RAG 问题中的示例文件、禁止读取文件也可能触发一次多余自查，这是语法提及规则的已知误触发成本。
- 空格路径、别名、大小写差异及未支持扩展名不保证被识别；此机制不是完整任务解析器。
- 一次提醒后模型仍可能不执行，不能称为确定性完成保障。
- RAG 语义验证保持原样。它只看到引用片段，未必能够核实本地代码观察；混合回答可能仍被阻断，不能为提高通过率放松验证。
- 执行账本不单独持久化，不改变 AgentEvent、会话或审计 schema。

## 评测合同

冻结题集 `eval/task-completion-v1.json` 包含十二个场景，每版运行一次，共二十四个目标回合。
覆盖显式/自然中文组合请求、英文组合请求、本地优先、文件缺失、服务故障、禁止读取、单独 RAG、普通消息、集合约束及取消。
环境为同一个本地 KnowForge Qwen3-4B Base 服务、16K 窗口、公共 techdocs 和隔离的本地测试文件。
不用 Adapter，不读取用户私有集合、配置或历史，不变更原有冻结数据集。

除原有自动诊断门外，新增独立的本地读取成功、失败和禁止读取检查。
自动门是路径、调用与文本代理，不是专家正确率。每版一次且没有逐请求固定随机种子，不能据此声称统计显著提升。

可选 `--diagnostics` 仅在评测中记录请求是否带自查标记和输出预算；不保存完整系统提示。
同一标记可以出现在后续多次请求中，不能将标记请求数等同于自查触发次数。
公共答案与有界工具结果沿用既有评测保存方式，原始 artifacts 不提交。

```powershell
node scripts/prompt-live-eval.mjs --baseline .codex-temp/task-execution-baseline-cee3525 --dataset eval/task-completion-v1.json --task-completion-review --diagnostics --repetitions 1 --output artifacts/prompt-live/task-completion-new-run
node scripts/prompt-live-summary.mjs artifacts/prompt-live/task-completion-new-run/report.json
```

两版需先构建，运行期间不得重建 dist；输出目录必须尚不存在。
该开关只对 candidate 生效。首轮冻结版本尚无开关，实验直接开启；后续复现必须显式传参，不能拿关闭实验的结果冒充复测。

### 逐项复核

| 场景                                   | 观察与结论                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| combined-explicit                      | 基线读了非目标证据后被拦截；候选重复六次带 `techdocs/` path 的空查询，未读本地文件。不能把空结果断言为整库无资料。                                             |
| combined-natural                       | 候选读到目标证据并发出一次带自查标记的请求，仍未 Read 本地文件，在 45 秒截止时取消。基线把本地文件塞进远端 path，未读证据或本地文件。                          |
| combined-english                       | 两版反复把集合名称当 path，均耗尽六轮工具预算；没有进入有效收尾。                                                                                              |
| local-first                            | 两版先读了本地文件。基线未 RagRead，却把实际没有 with 的测试说成与文档一致；候选读了目标文档，但最终被语义验证判为 unsupported。工具步骤正确仍不等于回答合格。 |
| missing-local                          | 两版都未实际 Read missing.py。候选自查后依然未读，最终 grounding 阻断；不能声称已证实文件不存在。                                                              |
| service-local                          | 两版均在 HTTP 503 后独立读取本地文件，自动门通过。没有执行测试，答案中的“验证响应为 200”只能理解为描述代码断言，不能写成测试已通过。                           |
| forbidden-local                        | 两版均未读取禁止文件，但均错误地将示例文件用于 RAG path，未满足证据回答要求。                                                                                  |
| standalone-rag                         | 两版均读到正确段落，给出 with statement 和准确引用。                                                                                                           |
| ordinary-file-mention / ordinary-array | 两版均不调用工具，正常回答。                                                                                                                                   |
| scope-prohibition                      | 两版均报告未授权集合不可用，没有转查 techdocs 或读取本地文件。                                                                                                 |
| cancel-combined                        | 两版均在约 150 毫秒取消，无工具副作用。                                                                                                                        |

额外发现一个评测覆盖限制：`forbidden-local` 和 `scope-prohibition` 的文件名前直接连接中文句号，当前词法边界未识别到文件，因此这两题没有触发自查。
它们只能证明该次运行没有违反限制，不能证明真实模型在自查触发后仍遵守禁止读取。显式触发的禁止读取路径目前只有 Mock 回归，后续重新开发须补真实反例，不能悄悄改冻结题集抹掉这个缺口。

诊断中仅两个候选回合出现自查标记，分别是 combined-natural 和 missing-local，均没有因此补出本地 Read。
部分失败发生在第一次工具调用参数，早于执行账本注入；反复追加收尾提示并不能修好这些前置错误。

## 采用决定与下一步

不默认启用本实验，原因是核心收益为零、资源成本上升，且真实禁止读取反例覆盖不足。
保留默认关闭的实验能力、冻结题集、检查器与失败报告，便于后续可追溯复验；不推送、不发布、不修改用户配置或 KnowForge 服务。

后续优先小范围处理：

1. 明确集合名称、远端相对路径、本地文件三者的边界，先测错误 path 与重复空查；不能未经授权直接去掉用户真实过滤条件。
2. 分开检验证据支持的文档结论和真实 Read 支持的本地观察，设计对应验收后再改 grounding；不得简单跳过验证。
3. 上述两点稳定后再试组合任务收尾，补齐中文边界及真实禁止读取反例，至少重复多轮；未过门前不扩大自动注入。

跨轮追问、多步任务规划、意图分类器和再次训练仍不属于本轮交付。
