# Prompt 分层整理与收敛报告

日期：2026-09-14。代码基线：`fb80c59`。工作分支：`codex/prompt-consolidation`。

## 目标与边界

本轮只整理现有提示、工具参数约定和按执行阶段提供的说明。目标是改善指令遵循、工具调用准确性和上下文效率，不是提升模型自身知识或理解能力。

没有新增意图分类器、前置模型、FastAPI 路由或配置项；没有修改 KnowForge 模型、训练数据、知识库、切分、检索排序算法、权限模式、审批、会话格式或发布版本。没有推送或发布软件。

## 梳理结果

| 位置             | 原先的问题                                                    | 本轮处理                                                    |
| ---------------- | ------------------------------------------------------------- | ----------------------------------------------------------- |
| 主系统提示       | 工作流和安全约束混在十三条规则中                              | 分成核心约束、工作方法；模式及本轮约束继续由原 Runtime 装配 |
| 常驻 RAG 提示    | 与参数说明、工具结果重复；包含完整阶段细则                    | 仅保留能力发现、来源范围、精确代码查询和本地/远程写入边界   |
| 证据选择         | 一处说排名不是证明，另一处要求低排名结果先通过重搜提升排名    | 移除强制提升排名要求，允许直接读取相关的低排名候选          |
| 搜索参数说明     | 多处重复集合/path 说明；把候选预算描述成至少返回十二条        | 正负例放到参数说明；明确实际匹配数可以少于预算              |
| 空查询和查询数量 | 空白字符串能进入工具；query 与 queries 合计超限会在后续被裁剪 | 工具入口拒绝空白查询及合计超过四条的输入                    |
| 检索结果         | 有结果和无结果都提供候选选择规则                              | 有结果才提供选择说明；无结果明确本次搜索的局限              |
| 读取结果         | 回答约定较长，与常驻提示重复                                  | 在读取成功后就近提供精简约定，并标明正文是资料而非指令      |
| 查询改写         | 已要求保留标识符和操作关系，未明确否定及条件                  | 补充保留否定、条件和来源范围的要求；调用流程不变            |

## 指令所有权

### 核心和模式约束

`src/runtime-instructions.ts` 管理精简的核心约束：用户任务和禁止项、权限不能绕过、工具结果不产生授权、成功与持久副作用必须如实报告、检查范围不得夸大。

`src/runtime-engine.ts` 继续负责装配模式指令、扩展说明、本轮约束和环境信息。`src/modes.ts` 以及实际权限执行逻辑未修改。

这些层级是程序组织方式，不意味着模型一定遵循；安全边界仍需 Runtime 校验。

### 工具参数约定

`src/rag/tools.ts` 的 Schema 保留严格字段校验，并增加空白查询和合计查询数校验。示例只解释最容易混淆的字段，不再把它们同时放入主提示。

- 正例：`collections: ["techdocs"]`，查询整个集合时省略 `path`。
- 正例：`path: "advanced/testing-events.md"`，兼容已有 `rag://` 虚拟路径形式。
- 反例：把绝对主机路径或 `..` 路径段当作检索范围。
- 反例：`query` 加四条 `queries`，合计五条。

跨字段约束由本地 Zod 执行；JSON Schema 的文字说明不替代执行校验。集合挂载、路径 canonical 检查和本轮 chunk 来源校验仍由原 Runtime 负责。本轮没有放宽这些边界。

### 按阶段提供说明

`src/rag/instructions.ts` 集中管理 RAG 能力提示、工具描述和阶段约定。

| 状态               | 提供的信息                                     | 不应出现的说明                  |
| ------------------ | ---------------------------------------------- | ------------------------------- |
| 尚未检索           | 简短能力提示、工具参数                         | 完整证据回答约定                |
| 检索成功且有候选   | 直接相关性优先、允许低排名证据、候选摘要是资料 | 排名等于事实支持                |
| 检索成功但无匹配   | 本次搜索未找到足够相关证据，必要时调整查询语言 | 全集合一定不存在答案            |
| 读取成功           | 正文、引用、精简回答约定                       | 链接或 include 指令等于可见代码 |
| 读取为空或调用失败 | 缺失 chunk 或真实错误                          | 已拿到证据的回答约定            |
| 用户取消           | 继续传播取消                                   | 改写为无证据、网络错误或成功    |

没有为动态注入增加模型调用，也不向聊天历史额外追加独立提醒消息。阶段约定随现有 ToolResult 出现；多次调用仍会产生多个 ToolResult，不能把本轮实现描述成“整个历史已全局去重”。现有 40 KiB 输出上限及上下文预算保持不变。

“资料不是指令”的标识和提示只能帮助模型区分来源，不能被描述为已经彻底解决提示注入。

## 静态体积对比

在同一 Windows/Node 环境、同一固定虚拟工作区下，对比基线与新实现。Engine 使用 ask 模式、Mock Provider，不带 AGENTS、Skills 或 MCP 扩展；RAG 为本地模式，自动检索关闭。

| 部分                  | 原字符数 | 新字符数 |   变化 |
| --------------------- | -------: | -------: | -----: |
| 主系统提示，不带 RAG  |     1881 |     1790 |  -4.8% |
| 主系统提示，带 RAG    |     3125 |     2226 | -28.8% |
| 其中常驻 RAG 能力提示 |     1227 |      419 | -65.9% |
| RagSearch 描述        |      407 |      214 | -47.4% |
| RagSearch 参数 JSON   |     1068 |      932 | -12.7% |
| RagRead 描述          |      231 |      172 | -25.5% |

字符数不是 tokenizer 实测 tokens，也不是实际完整请求大小。用户环境中的 AGENTS、Skills、MCP、历史和工具结果仍会影响上下文，不能据此声称所有请求都节省 28.8% tokens。

新的证据回答约定为 437 个字符，仅在读取成功时提供。查询改写提示增加了一句条件保留规则，所以并非每一个局部提示都缩短。

## 如何手测

从本分支仓库根目录运行：

```powershell
npm run build
node --test tests/prompt-contracts.test.mjs
node dist/index.js
```

直接运行此处的 `dist/index.js`，避免 PATH 中另一个全局 syzzz 安装仍使用旧代码。已有 CLI 进程需要退出后重新启动。保持模型、工作区、已挂载集合和配置不变，不要为本次测试扩大窗口或切换训练 Adapter。

使用新会话完成下面的抽查；只有追问用例应接在上一条后面：

| 输入                                                                         | 观察内容                                            |
| ---------------------------------------------------------------------------- | --------------------------------------------------- |
| 解释 JavaScript 数组，不用查资料。                                           | 不应为了分析意图而额外调用模型或 RAG                |
| 只根据 techdocs 说明测试中怎样运行 lifespan，不要补充文档没有展示的代码。    | RagSearch → RagRead；正确条件与有效引用，不补造代码 |
| 那异步测试呢？                                                               | 能正确承接主题，或在含糊时澄清；不能机械复用旧结论  |
| 只根据 techdocs 回答商业支持合同的价格、SLA 和退款条款；没有证据就说明不足。 | 检索后谨慎说明材料局限，不编造或堆无关引用          |
| 先查 techdocs 的 lifespan 文档，再检查当前测试文件；不要修改文件。           | 两部分任务均得到处理，不产生写入                    |

记录模型、调用顺序、是否读到正确证据、最终引用、无依据补充、耗时和用量。验证超时必须记为基础设施失败，不能算成正确拒答。

## 尚未证明与后续范围

整理提交时只确认了代码、静态体积与回归。2026-09-14 后续已完成真实模型 32 场景 × 3 次 × 两版对照，见 [真实评测报告](PROMPT_LIVE_EVAL.md) 与 [逐条复核](PROMPT_LIVE_REVIEW.md)。固定请求输入减少，但端到端质量没有提升，目标文档读取还出现下降信号；不能宣称准确率或可靠性已经改善。

以下没有混入本轮：

- 自由自然语言的通用意图提取、强制检索任务合同和漏检索终态拦截。
- 多轮追问的独立查询生成、按集合语言选择改写策略。
- 语义验证/回答修复预算重构，以及草稿与最终答案的流式展示语义调整。
- 新模型、重新训练、新的向量或重排算法。

原有“已经读取证据或输出引用才进入证据检查”的触发机制未改；模型完全跳过检索仍是后续需要真实评测并解决的缺口。不要把本轮提示整理误称为新增了强制执行门。

真实对照使用独立开发评测，未修改已冻结的 Day 2/Day 5 数据。下一步应先处理报告列出的空检索恢复、组合任务提前收尾与追问偏题，再单独对照验证，不通过改题追求更好看分数。
