# 空检索诊断与有界恢复

## 范围

这是 Prompt 整理之后的第一、二步：先观察实际检索输入，再处理空检索。
不增加意图分类器，不训练模型，不修改知识库、生成模型、权限、普通审计或会话结构。
组合任务收尾和跨轮追问的改进留到后续，不能把本轮当成它们的验收。

对照基线为 `c9b1be8`，首轮候选实现为 `e386ad2`。真实测评完成后，以 `6e23f9c` 收紧同回合恢复预算；下表不冒充后一个版本的完整复测。保留独立基线检出，不回滚工作区。

## 诊断发现

在公共 techdocs 上，对五个既有场景开启诊断，确认了不同失败层次：

| 场景             | 实际观察                                                                    | 含义                                                                   |
| ---------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| constraint-code  | 模型填入 `testing-events.md`，真实路径在 `advanced/` 下                     | 路径按集合根目录匹配，不是文件名模糊匹配；翻译查询不能修复这个过滤条件 |
| constraint-mixed | 模型把本地工作文件 `test_lifespan.py` 放入远端知识库的 path                 | 混淆本地任务文件与检索源，不应自动取消用户约束                         |
| explicit-schemas | 用户给出了 SDK 条件，模型检索时已丢失；正确条件段落排第二，模型只读取第一项 | 查询条件丢失与证据选择问题，不只是空召回                               |
| natural-lifespan | 首次检索已命中并读到正确文档，最终仍被引用门阻断                            | 生成/引用收尾问题，不需要额外改写检索                                  |
| mixed-schemas    | 自动门通过，但回答末尾另有截断的引用片段                                    | 自动通过不等于完整质量合格                                             |

以上是一次诊断运行的事实，不是每次请求必然重现的模型行为。原始记录保存在被 Git 忽略的 `artifacts/prompt-live/recovery-diagnosis-20260914/`。

## 实现规则

1. 原查询先检索。结果非空即返回，不再因为查询含中文就先调用模型。
2. 第一次请求失败时直接返回错误。未挂载集合、非法路径、HTTP 错误和取消均不触发恢复。
3. 只有一个独立查询且不超过 4096 字符时，才允许在空结果后调用一次隔离改写器；多查询不合并，不丢弃其中条件。
4. 改写器没有工具，输入仅为该查询，不含聊天历史；输出预算 256 tokens，最长等待 10 秒。即使 Provider 忽略取消，调用方也会结束等待。
5. 最多三个改写，每个不超过 512 字符。损坏 JSON、超长或非法成员不被静默截断后使用；空列表或只有原查询不再次请求。
6. 至多再检索一次，携带原查询及去重后的改写，保留同样的集合、path、limit。第二次仍为空就返回空；第二次服务失败仍是服务错误。
7. 单次 RagSearch 最多两次后端检索、一次改写。最终实现中，同一 Agent 回合的所有 RagSearch 和自动预检索共享一次恢复预算；失败也消耗预算，回合结束释放。模型仍可请求普通检索，受既有工具预算约束。无回合上下文的人工 `/rag search` 按单次调用计算。
8. path 的 Schema 明确集合根目录语义。空结果时若有路径，解释其匹配方式；不自动从 basename 猜路径，不改成不受限全库检索，不转读本地文件。

查询中的否定、条件和标识符由精简提示要求保持，但不声称这些自然语言条件已经获得形式化语义验证。
一次错误路径请求可能仍多花一次恢复调用；如果它返回空，不能据此断言整库没有材料。
正常返回但不相关的结果不会触发本轮的空结果恢复，这是刻意保留的范围限制。

## 本地诊断与隐私

`scripts/prompt-live-eval.mjs` 增加两个可选参数：

- `--arms candidate` 或 `--arms baseline`：只运行一个版本；默认仍交替运行两个版本。
- `--diagnostics`：显式保存评测查询、改写、后端请求白名单字段、返回定位及读取 ID。

诊断只在评测进程中启用，不改生产日志或 AgentEvent。每回合最多 80 个诊断事件、256 KiB；超限不继续追加。
不保存 HTTP 请求头、密钥、模型原始响应或 reasoning。请求捕获只针对 localhost 的 `/knowledge/search`；退出恢复原 fetch。
现有评测本来就会保存公共测试的答案和有界工具结果，新增诊断不是面向任意私密资料的脱敏保证。
只用公共 fixture；原始 artifacts 不提交仓库。默认未指定该参数时不增加 diagnostics 正文。

## 复现

先启动既有 KnowForge 模型与 FastAPI 服务，并构建两个版本。不要在运行测评的同时重建 dist。

```powershell
node scripts/prompt-live-eval.mjs --baseline .codex-temp/prompt-recovery-baseline-c9b1be8 --diagnostics --repetitions 1 --output artifacts/prompt-live/recovery-new-run
node scripts/prompt-live-summary.mjs artifacts/prompt-live/recovery-new-run/report.json
```

输出目录必须不存在。`--repetitions 1` 是显式缩小重复次数的开发对照，不是默认三轮完整质量门。
结果应同时核对是否调用、是否读对证据、是否交付合格结论、是否保持来源与权限；不能只看非空率。
