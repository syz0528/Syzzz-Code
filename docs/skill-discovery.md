# Skills 渐进发现（M3）

此功能已接入本地开发源码，尚未发布到 npm。无需增加 Embedding 或 Jev 配置；发现本身是本地词法检索，不调用远程模型。

## 工作流程

1. 小目录直接提供有界元数据；大目录先提供分类概览和有界名称索引。
2. Agent 按需要调用 `DiscoverSkills`，检索名称、展示名称、简短描述及资源文件名，或分页浏览。一次最多返回 8 个候选。
3. Agent 用准确名称调用 `ActivateSkill`，此时正文才进入模型上下文。
4. 引用资料仍通过 `ReadSkillResource` 按需读取。脚本只有经现有工具、模式、Hook 和审批链执行后才算真正运行。

发现候选、加载正文、完成任务是三件不同的事。初始名称索引省略某个 Skill，或某个关键词没有命中，都不表示它不存在。可换关键词、按类别浏览或继续翻页。明确知道名称时，用户仍可直接输入 `$skill-name 任务`，无需先发现。

这是**模型上下文的渐进加载**，不是磁盘扫描完全懒加载：原有扫描器仍解析 `SKILL.md` 以验证描述和元数据；发现结果不会带入正文或资源内容。

## 手动使用

在交互会话中：

```text
/skills discover 中文测试
/skills discover systematic-debugging
/skills browse 0
/skills browse 8 testing
/skills catalog auto
/skills catalog full
/skills catalog progressive
/skills list
```

`discover` 返回第一批关键词候选；完整目录用 `browse [offset] [category] [revision]` 浏览。结果会给出下一页 offset 和 revision，连续翻页时传入相同 revision；若目录变化，重新从 0 开始，不能继续使用旧游标。`list` 区分当前目录模式、最近发现候选和本轮已加载名称。

命令行也可只做本地发现，不启动 Provider：

```bash
syzzz skills discover "中文测试" --json
syzzz skills discover --offset 8 --limit 8 --category testing --json
```

这些手动命令输出不进入聊天历史，不自动激活或执行 Skill。

## 模式与预算

配置中的可选字段 `skills.catalogMode` 不改变 schemaVersion，旧配置不必迁移。

| 模式           | 行为                                                                 |
| -------------- | -------------------------------------------------------------------- |
| `auto`（缺省） | 可隐式使用的目录超过 32 项，或原有元数据预算无法容纳时，使用渐进目录 |
| `full`         | 保留原有有界元数据目录，供回退和对照；不是无上限全量正文             |
| `progressive`  | 始终使用分类概览、有界名称索引和按需发现                             |

渐进目录正文最多 2400 字符，并继续受上下文窗口 2% 的估算预算限制。名称索引可以省略，完整候选仍可分页访问。工具结果每页最多 16 KiB；描述、依赖声明和资源文件名也有独立上限。缓存仅保存本地检索索引，元数据变化后自动失效。

分类使用可审查的中英文词表，例如 testing、review、debugging、documentation、frontend、data、security、delivery、planning、general。它们可重叠，**不是语义分类模型**。同义词扩展可能引入噪声；词法分数是排序依据，不是相关性概率或任务成功率。未检查的依赖仅显示声明，不暗示安装成功。

类别和同义词分别定义：计划与访谈可以同属 planning，但查询“计划”不再自动扩展成 interview/grill/questions；框架、SQL、发布和容器等同类不同概念也不互相替代。有限词形表覆盖 plans/planned 等，避免搜索能命中而分类排除。显式类别仍为硬过滤，不会被静默撤销；结果不适配时可用具体工作流意图且不带类别再查。索引 revision 同时绑定算法版本与元数据。

## 搜索收敛与验收收尾

发现结果不要求 Agent 穷举目录。已找到合适候选时，应加载正文并执行任务，把预算留给产物、验收和最终说明；仍可为确实缺少的能力继续搜索或加载其他 Skill。

“合适”按当前任务阶段和请求的产物判断，不按共同领域词判断。例如已有规范的工程交接优先寻找计划工作流，不因为接口有分页就重新设计服务器 API；具体接口事实由用户规范提供。下一页存在不是必须浏览的理由；已加载后，只有独立能力缺口才需要第二个工作流。这些是提示，不是强选第一名、固定硬次数或新的语义分类器。

- 本轮相同规范化关键词、类别、offset、limit 和目录 revision 重复查询时，提示复用候选；不报错，也不强制选择第一名。
- 已加载工作流时，提示先执行和检查，仅为缺少的能力继续发现。
- 本轮模型已发现至少 3 次且本页有候选时，提醒停止可选比较，尽快选择；无结果时仍可换关键词或分页。
- 手动 CLI/Slash 浏览不计入模型轮次；计数每轮重置。不保存原始查询，不增加额外模型请求。

每个 DiscoverSkills 的内部完成事件带独立 `metadata.discoveryReceipt`，保存最多 8 个候选的名称、全局排名、类别、匹配方式和词法分数，以及 revision、请求摘要 hash、提示类型和最多 8 个已加载名称。同一响应中的多次发现不会只剩最后一次状态。回执不包含查询正文、描述、正文、资源内容或绝对路径；审计和脱敏 NDJSON 仍不复制这些元数据。提示类型表示 Runtime 给出的建议，不代表读到了模型的停止理由。实验记录器读取内部事件，按工具调用 ID 关联后续激活/发现，观察实际行为。

启用 `finalizeOnToolBudget` 且设置 `maxProviderCalls` 的有界 Engine（如受限子任务或实验）会在原上限内预留最后一次无工具请求；不会偷偷增加请求或代用户执行测试。余下工具阶段请求不足时，提示先完成产物并使用正确 schema 执行用户要求的验收。压缩与正常生成共用预算，压缩后再次检查是否已进入收尾。

启用显式交付契约时，第一轮起提供有界 `delivery_budget` 提示：包含当前请求的剩余 Engine 请求数、预留最终报告数、工具阶段请求上限及剩余工具调用数。压缩和上下文恢复消耗请求后，在实际发送前重新计算；它不计数 Provider 内部重试尝试。未配置的上限显示 null，不表示时间或上下文无限。模型可据此合并独立且获准的读取或写入，安排真实检查和报告；合理的基线失败测试仍允许，不强制跳过工作流必需步骤。这是请求内临时提示，不进入会话或审计，也不改变工具暴露、审批、终态和调用上限。

预算收尾不等于完成：结果保留 `budgetStopReason`；交付契约仍标记 incomplete，检查缺失、旧版本、截断或保护文件变化均不能变成通过。普通未启用此选项的 Engine 保留原硬预算行为。模型或服务超时也不会由该预留机制自动修复。

已声明的检查正常退出并报告失败时，严格核对回执与范围后可修复再验收，而不是把所有非零退出都当作执行结果不明。检查仍标记 error，必须有新版本的成功验收才能通过；详见[交付记录与恢复边界](task-delivery.md)。

## 安全边界

- 模型只发现启用、允许隐式调用且在当前 allowlist 内的获胜版本；项目版本覆盖用户版本的原有规则不变。
- 手动发现可以查看仅显式调用的 Skill，但不能因此绕过该策略。全局禁用和隐式调用关闭仍有效。
- 发现工具为 `read/never`，ask、plan、code 均可用；仍经过输入校验、模式执行层和 Hook。
- 加载前再次核对当前元数据与隐式调用策略；符号链接和 junction 不能逃出获准 Skill 根。
- 候选元数据是不可信资料，不能授权工具、改变权限、安装依赖或自动执行脚本。
- 普通聊天不会被 Runtime 强制附加一次检索或模型调用；是否调用发现工具仍由后端模型判断。

## 检查点中的既有实验接口

开发分支保留 `QueryEngineOptions.experimentalSkillRouting`，用于既有隔离实验由宿主提供候选并通过正常 `ActivateSkill` 工具链加载。它不是 CLI 配置项，当前 CLI 不启用；没有新增默认 Jev 调用或替代原生选择。加载仍受原模式、Hook、审批、取消和工具预算约束，宿主激活回执不冒充模型发出的工具调用。

该接口是在 M0-M4 开始前已有的未提交实验改动，本次按用户确认随开发检查点保留，不是 M3 的稳定交付或已证明有收益的选择器。实验脚本与旧报告不因此混入产品提交；正式合并 main 前须另审此接口的保留范围与专项验证。

## 验证

```bash
npm run test:skills-discovery
```

专项覆盖百级目录分页、中英文匹配、目录变更、禁用与 allowlist、显式调用、真实 Engine 加载回执、Hook 拒绝、取消、CLI/Slash 本地路径和 JSON 大小边界。离线固定响应证明工程链路，不代表所有真实模型都能正确选 Skill。真实模型效率、选择准确性和最终交付要另做同目录、同任务、同预算对照；M3 不默认启用 Jev。

M3 的工程退出范围是可发现百级目录中的已知目标、可翻页访问被省略项、真实加载仍受原政策约束。该范围与本地自动化验收完成后可收口；不是云端任务全部成功、已证明速度或费用收益、跨平台发布验收或 Frozen。响应格式错误仍安全终止，不修补 JSON 后偷偷执行合法部分，也不自动扩大预算补交付。
